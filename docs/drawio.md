# drawio.cmk

`drawio.cmk` renders [draw.io](https://www.drawio.com/) diagrams (`*.drawio` / `*.dio`) to **PNG**,
split out of `docs.cmk`.  It wraps the headless `rlespinasse/drawio-export` exporter behind a small
render wrapper baked into the image, so the cmk side stays a one-line call.  A library plugin (no
`__main__`); import it with `$(call include.plugins, drawio.cmk)`.

## Public surface

<hr class="section-rule lvl-3">

| Target | Purpose |
| --- | --- |
| `drawio.render/<file>` | render one diagram to a sibling `<name>.png` |
| `drawio[/<path>]` | render `<path>`, or every `*.drawio` under `drawio.root` |
| `drawio.root` | the root the no-arg form walks (defaults to `${DOCS_ROOT:-docs}`) |

The no-arg `drawio` driver is generated by `io.factory.file_handler`, which wires the per-file
`drawio.render` handler to a root-walking loop over the `*.drawio` glob.

## How it works

<hr class="section-rule lvl-3">

The exporter image is declared with the `container` abstraction: an inline `define Dockerfile.drawio`
wired to the `drawio.exporter` instance via `src=`.  That single declaration gives the instance a
`.build` target plus `.img` / `.entrypoint` accessors, so the image and its baked `cmk.render`
entrypoint live in one place.  The `container` keyword is a `cmk.*` KIND, bound bare here by `open cmk`.

## Usage

<hr class="section-rule lvl-3">

```Makefile
$(call include.plugins, drawio.cmk)

# render one diagram to a sibling PNG...
drawio.render/docs/img/concepts.drawio

# ...or every *.drawio under docs/ (drawio.root honors DOCS_ROOT)
drawio
```
