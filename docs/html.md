# html.cmk

`html.cmk` is small **CSS/HTML tooling**, split out of `docs.mk`: containerized node helpers that
**minify** (clean-css) and **pretty-print** (prettier) CSS.  It is a library plugin (no `__main__`)
that contributes a `css.*` namespace; import it with `$(call include.plugins, html.cmk)`.

Each tool comes in two forms: a single-file form, and a "walk a root, process every `*.css`" form.

## Public surface

<hr class="section-rule lvl-3">

| Target | Purpose |
| --- | --- |
| `css.minifier/<file>` | minify one CSS file in place (clean-css) |
| `css.min[/<path>]` | minify `<path>`, or every `*.css` under `css.root` |
| `css.prettify/<file>` | pretty-print one CSS file (prettier) |
| `css.pretty[/<path>]` | prettify `<path>`, or every `*.css` under `css.root` |
| `css.root` | the root the no-arg forms walk (defaults to `${DOCS_ROOT:-docs}`) |

The no-arg `css.min` / `css.pretty` drivers are generated by `io.factory.file_handler`, which wires
the per-file handler to a root-walking loop over the `*.css` glob.

## How it works

<hr class="section-rule lvl-3">

Each tool's image is declared with the `container` abstraction: an inline `define Dockerfile.*` wired
to a container instance via `src=`.  That single declaration gives the instance a `.build` target plus
`.img` / `.entrypoint` accessors the recipes reuse, so the Dockerfile, image tag, and entrypoint all
live in one place instead of scattered `mk.docker` kwargs.  The `container` keyword is a `cmk.*` KIND,
bound bare here by `open cmk`.

## Usage

<hr class="section-rule lvl-3">

```Makefile
$(call include.plugins, html.cmk)

# minify one file in place...
css.minifier/docs/theme/css/compose.mk.css

# ...or every *.css under docs/ (css.root honors DOCS_ROOT)
css.min
```

Pointing the walk at a different tree is a one-liner: set `css.root` (or `DOCS_ROOT`) before the
no-arg `css.min` / `css.pretty` target.
